FURLONGIQ ON VERCEL + HORSE SUPABASE
=================================
The live site reads today's cards and the full speed-figure history from the
horse Supabase project (tkbhjbpiiierhjhjfjdd, Ireland). It does not use Nova.

1. Vercel project settings
   - Framework: Next.js
   - Root Directory: web
   - Build command and output: leave as the defaults
   - Ignore the "multiple services" suggestion — this is one Next.js app

2. Vercel environment variables (Settings -> Environment Variables)
   Add both of these for Production, Preview and Development:

     SUPABASE_URL = https://tkbhjbpiiierhjhjfjdd.supabase.co
     SUPABASE_ANON_KEY = eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJzdXBhYmFzZSIsInJlZiI6InRrYmhqYnBpaWllcmhqaGpmamRkIiwicm9sZSI6ImFub24iLCJpYXQiOjE3OTQ4MjcyNjQsImV4cCI6MjExMDQwMzI2NH0.p_7LGJACFENL0IxbODfCiMAB8UpCz6CusG5ayS_0NlM

   The anon key is safe to use here (it can only read). Do not add the
   service role key to Vercel. NEXT_PUBLIC_SUPABASE_URL and
   NEXT_PUBLIC_SUPABASE_ANON_KEY are also accepted if you prefer those names.

   After adding the variables, Redeploy the project.

3. Service role key on this PC (for the daily upload)
   - In the horse Supabase project: Project Settings -> API -> service_role
   - Copy .env.example to .env in the Speeds folder
   - Paste the service role key as SUPABASE_SERVICE_ROLE_KEY
   - Never commit .env and never put that key in Vercel or GitHub

4. Each day, after the cards and figures are ready on this PC
     GET_TODAYS_CARDS.bat
     PREDICT_TODAY.bat        (first time trains the model, ~2 minutes; later runs also fine)
     npm run figures          (or just npm run dev, which also scores today's cards and rebuilds pace labels)
     UPLOAD_TO_SUPABASE.bat
   The Vercel site updates on the next page load — no redeploy needed.
   Predictions travel with fig_meta automatically. Optionally run tools/pred_today.sql
   once in the horse Supabase SQL editor to also store them in a pred_today table.
   For pace badges on the live site, run tools/pace.sql once in the same SQL editor,
   then re-run the upload. The site works without that table (form runs just have no
   precomputed pace badge; comment fallback still works).
   For win % and fair odds on the live site, run tools/win_pct.sql once in the same
   SQL editor, then re-run the upload (WIN_PCT.bat or PREDICT_TODAY.bat scores today's
   cards first). The numbers are also stored in fig_meta, so the site can still show
   them if the table is missing.

5. Push these site changes to GitHub (from the Speeds folder / horse repo)
     git add -A
     git status
     git commit -m "Read FurlongIQ cards and figures from horse Supabase on Vercel"
     git push origin main

   Do not add .env, data/, *.sqlite or node_modules (they are gitignored).
   After the push, Vercel will rebuild. The race cards appear once the
   upload in step 4 has been run at least once.

Local use is unchanged: npm run dev from the Speeds folder still reads the
SQLite files on this PC when SUPABASE_URL is not set in the local environment.
