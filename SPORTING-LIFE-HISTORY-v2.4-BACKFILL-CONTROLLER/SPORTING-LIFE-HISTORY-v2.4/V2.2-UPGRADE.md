# Sporting Life Collector v2.2 — runner accuracy repair

## Changes
- Replaces text-wide ordinal scanning with horse-profile anchor boundaries. `2nd`, `3rd`, `5th` inside a horse's running comment cannot start another runner.
- Captures the `Also Ran` runner statuses `F`, `B`, `BD`, `PU`, `UR`, `R`, `RO`, etc. Preserves the raw site code as `status_raw` and the normalized status separately.
- Attempts to capture text-only `NR` records with a race-scoped synthetic identity; does not confuse non-runners with starters or finishers. Review any text-only NR ambiguity.
- Preserves `margin_from_preceding` as site text, adds `margin_lengths_numeric`, cumulative `win_dist_from_winner`, and your `nk = 0.01` convention.
- Retains `legacy_win_time_plus_dist = winning_time_seconds + cumulative margin`, exactly as requested. The result is **not an independently measured horse time in seconds**. No seconds-per-length conversion has been assumed.
- Missing/unknown symbolic margins (e.g., `hd`) remain unknown; never silently become zero. Non-finishers and NRs have no winning time plus distance.
- Adds internal CSV accuracy validator; all races remain **ineligible for standard-time calculation** pending source and course-configuration verification.
- Adds `--reparse` to refresh previously collected races **without deleting the database**.

## Upgrading with your existing history
1. Unzip v2.2 to a **fresh folder**.
2. Copy the entire `data` folder from v2.1 into the new v2.2 folder. **Do not overwrite or delete your existing SQLite database until you have backed it up.**
3. Run `TEST_ACCURACY_OFFLINE.bat` (no website access).
4. Run `REPARSE_2022_TEST.bat` only where you have permission to make live automated requests; this refreshes the first three queued races for 21 October 2022. Existing results in the database are replaced atomically per race; unrelated races remain untouched.
5. Run `QA_CSV_EXPORT.bat` and inspect `data/exports/races_all.csv`, `runners_all.csv`, `v22_accuracy_audit.json`.

If the stored records were collected without saving full HTML, historical **truncated comments cannot be recovered from the CSV alone**. They require the original HTML or a fresh authorised retrieval.

## Important data rules
- `nk=0.01` is your chosen legacy numeric convention, **not 0.01 seconds or an official standard conversion**.
- The `legacy_win_time_plus_dist` field deliberately adds numbers representing lengths to a clock time; it reproduces your former method, **not a physically meaningful elapsed time**. Later calibration should derive a track/distance-specific seconds-per-length factor from actual data if needed.
- `NR` = did not run; `F` = fell; `B` or `BD` = brought down; `PU` = pulled up; `UR` = unseated rider. Their records remain in history, but they have **no calculated finishing time**.
- `qa_status=parsed_not_verified` is not the same as independently verified. Course configuration and amended results still need auditing.
- Website permissions and access restrictions are unchanged. The scripts do not evade access controls.
